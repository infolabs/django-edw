# Django EDW — исследовательская ветка Django 5.2

EDW — библиотека для классификации объектов, семантических выборок, витрин данных и REST API. Это **не готовое приложение Service Desk** и не универсально проверенная миграция всего исторического репозитория.

## Поддерживаемый состав этой ветки

Проверяемый контур: `backend/edw`, модели Term/Entity/DataMart, REST/bulk/nested операции, обязательные зависимости из `pyproject.toml`, synthetic contract app и suites `runtime_tests/`, `runtime_tests_safety_alias/`. Проверки используют SQLite и locmem cache.

Зафиксированная исследовательская матрица: **Python 3.12.3, Django 5.2.18, DRF 3.18.3**. Используется [InfLabs djangorestframework-bulk](https://github.com/infolabs/django-rest-framework-bulk/tree/e39983cb549ddc5245e726ab26261e318964258a) `0.3.0a1`, exact source `e39983cb549ddc5245e726ab26261e318964258a`, а не обычный PyPI bulk `0.2.1`.

**Единственный описанный здесь путь сборки, изолированной установки и проверки: [INSTALL.md](INSTALL.md).** Он требует заранее подготовленных wheelhouse и закреплённого frontend bundle. Ветка сама по себе не является самодостаточным offline kit. Не подставляйте случайные версии из package index и не устанавливайте её поверх рабочего окружения.

## Что не поддерживается этим результатом

- Старые демонстрационные приложения Django 1.9 и их инструкции удалены из текущего дерева. Они доступны только в истории Git; переносить их в новый проект не следует. [Объём очистки](docs/legacy-cleanup/README.md).
- Extras `auth`, `admin`, `search`, `task`, `geo`, а также упакованные `email_auth`/`social_extra` не получили полной runtime-приёмки. Наличие исходника или extra не означает подтверждённую совместимость.
- PostgreSQL concurrency/deadlocks, production migration, внешние события, нагрузка, полноценная браузерная работа и готовность SD-процессов не подтверждены.
- Старые `scripts/check.sh` и `scripts/check_runtime.sh` — исторические инструменты, не актуальный путь установки. Их известные ограничения описаны в [архиве анализа](docs/neural-analysis/LIMITATIONS.md). Для текущей проверки используется `scripts/check_safety.sh` согласно INSTALL.
- `runtime_tests/*settings.py` и synthetic contract app — только тестовый контур, не production settings и не образец настройки доступа.

## Механизмы EDW

- **Term:** дерево признаков и семантических правил.
- **Entity:** классифицированные объекты и отношения.
- **DataMart:** правила отбора и представления объектов.
- **REST API:** сериализация, фильтры, вложенные и массовые операции в пределах реализованной политики доступа.

Подробнее о предметных понятиях — [docs/index.rst](docs/index.rst). Наличие механизмов сокращает часть инфраструктурной работы, но не заменяет доменную модель и проверку конкретного приложения.
