# Удаление старого demo-контура

После прямого согласия владельца из текущего дерева ветки удалены 55 tracked файлов:

- `backend/requirements/django19/`: 2 старых requirements-файла;
- `backend/sandbox/`: 52 файла старых sample/todos приложений и их вспомогательных материалов;
- `backend/docs/sample.txt`: 1 устаревшая инструкция установки.

Причина — документированная цепочка установки приводила к Django1.9.8, DRF3.3.3 и удалённым API `url/patterns/ugettext_lazy`. Простая замена пинов не делала старые приложения совместимыми. Вместо выдачи этих demos за рабочие примеры выбран меньший честный scope — проверенный библиотечный контур.

Удаление выполняется обычным последующим commit. История не переписывается и не очищается от старых объектов; восстановить старый пример можно из истории, но он не является поддерживаемым способом установки. SQL/fixture contents для удаления не исследовались и не переносились в новый report.

Runtime Python-код `backend/edw`, `email_auth`, `social_extra`, модели, API, их миграции, `pyproject.toml`, исполняемый код прежних тестов и durable safety gate не изменены этой очисткой. README старого contract harness обновлён, чтобы больше не рекомендовать устаревший runner. Package exclusion `sandbox*` и проверки отсутствия sandbox в wheel сохранены как защита от регрессии.

Исторические `edw-inventory.json`, runtime/safety reports, `docs/neural-analysis/` и `docs/_build/` не исправляются задним числом. Их упоминания старых путей — provenance, не активная инструкция. Каталог `docs/neural-analysis/` зафиксирован предыдущим handoff commit `3a02c052d4146c0c3d09f0df02fe4533126e0221` на tested source `50d26164383dc1df77795a5a079ffe2be1e2a9da`; его прежний wheel hash не относится автоматически к новой сборке.

Актуальные входы: корневые [README](../../README.md) и [INSTALL](../../INSTALL.md). Старый пустой `backend/docs/install.txt` и `docs/index.rst` направляют в INSTALL. Frontend guide больше не рекомендует старый check.sh как полную проверку ветки.

Статический барьер `scripts/check_clean_source.py` проверяет отсутствие удалённого дерева и ссылок на него из текущих источников/инструкций. Это узкий текстовый regression guard: он не доказывает полноту динамически сконструированных imports, не проверяет все внешние consumer-проекты и не заменяет runtime gate. Его собственные проверки находятся в `scripts/test_clean_source.py` и используют только временные синтетические файлы.

Результаты новой установки и runtime-проверок сохраняются отдельным последующим отчётом. Не приписывать исторические 221 E12 cases новому commit без отдельного запуска.
