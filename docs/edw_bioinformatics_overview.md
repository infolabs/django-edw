# Django EDW: обобщенное описание с фокусом на биоинформатику

## Что такое Django EDW

Django EDW можно использовать как MDM/НСИ-слой для централизованного управления мастер-данными и метаданными. В основе подхода:

- систематизация объектов разных моделей в едином семантическом пространстве;
- сложные семантические выборки;
- сортировка и группировка по общим признакам;
- публикация данных через REST API.

Такой подход особенно полезен там, где много неоднородных сущностей, связей и критериев отбора, как в задачах биоинформатики.

## Базовая модель: термины, дерево терминов, витрины

### Термины

Термин - это семантический признак объекта. Один объект может иметь несколько терминов, которые описывают его свойства.

Пример (универсальный):

- объект `Публикация` может иметь термины `Новость`, `Культура`.

### Дерево терминов

Дерево терминов объединяет все признаки всех объектов в иерархическую структуру. Часть терминов может генерироваться автоматически на основе моделей, часть задается администратором.

Семантические правила родительских узлов (например, взаимоисключение или множественный выбор) определяют допустимые комбинации терминов.

### Витрины данных

Витрина данных - набор правил отбора объектов. Витрина сравнивает термины объектов с терминами запроса и возвращает релевантную выборку, также задавая:

- сортировку;
- представление;
- дополнительные зависимости и условия.

## Адаптация к биоинформатике

В биоинформатике EDW удобно использовать как слой управления метаданными и семантической навигации между сущностями (образцы, эксперименты, пайплайны, результаты анализа).

### Какие объекты обычно описывают

- биологические образцы (`Sample`);
- доноры/пациенты и когорты (`Subject`, `Cohort`);
- эксперименты (`Experiment`);
- запуск секвенирования (`Run`);
- файлы и артефакты (`FASTQ`, `BAM`, `VCF`, отчеты QC);
- аннотации вариантов и признаки (`Annotation`, `Variant`);
- биоинформатические пайплайны и версии инструментов (`Pipeline`, `ToolVersion`).

### Пример дерева терминов для биоинформатики

- Тип данных:
  - Геномика
  - Транскриптомика
  - Метагеномика
- Платформа:
  - Illumina
  - Oxford Nanopore
  - PacBio
- Материал:
  - Кровь
  - Ткань
  - Клеточная линия
- Статус качества:
  - QC passed
  - QC warning
  - QC failed
- Клинический контекст:
  - Онкология
  - Редкие заболевания
  - Инфекционные болезни

### Семантические правила в биоинформатике

- Для узла `Платформа` часто подходит правило "один из" (взаимоисключающие значения).
- Для узла `Клинический контекст` обычно подходит множественный выбор.
- Для узла `Статус качества` полезно жесткое взаимоисключение, чтобы избежать неоднозначности в пайплайнах.

## Практические сценарии

### 1) Поиск воспроизводимых наборов данных

Можно быстро отбирать объекты по комбинации терминов, например:

- `Тип данных = Геномика`;
- `Платформа = Illumina`;
- `Статус качества = QC passed`;
- `Pipeline version = v2.3`.

Это помогает формировать воспроизводимые когорты для повторного анализа.

### 2) Управление клинико-геномными выборками

Через витрины удобно выделять подмножества для конкретных гипотез:

- только опухолевые образцы;
- только соматические варианты;
- только образцы с полной клинической аннотацией.

### 3) Подготовка API для аналитики и интеграций

REST API может выступать единым входом для:

- BI/дашбордов;
- внутренних LIMS/ELN-систем;
- downstream-сервисов статистики и ML.

## Рекомендации по внедрению в биоинформатике

- Проектируйте дерево терминов вокруг реальных этапов пайплайна (ingest, QC, alignment, variant calling, annotation).
- Добавляйте термины для происхождения данных (provenance): версия референса, версия инструмента, параметры запуска.
- Фиксируйте правила валидации терминов на уровне моделей и API, чтобы избежать семантического дрейфа.
- Поддерживайте согласованную словарную политику (синонимы, устаревшие термины, controlled vocabulary).
- Встраивайте контроль качества данных как часть терминологической модели, а не как отдельный внешний процесс.

## Ограничения и что учесть заранее

- Иерархия терминов требует дисциплины сопровождения и редакционной политики.
- При большом объеме омикс-данных хранить нужно не сами тяжелые файлы, а метаданные и ссылки на хранилища.
- Для чувствительных медицинских данных важны разграничение доступа, аудит изменений и деидентификация.

## Краткий итог

Django EDW в обобщенном виде - это семантический каркас для MDM/НСИ, который хорошо переносится в биоинформатику. Основная ценность: единый словарь терминов, управляемые витрины данных и API-доступ к консистентным, воспроизводимым выборкам для исследований и продуктовой аналитики.
